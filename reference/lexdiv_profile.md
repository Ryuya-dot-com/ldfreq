# Build and Evaluate Explicit Lexical-Diversity Method Plans

Builds bounded, reproducible plans for computing multiple parameter
settings of the versioned lexical-diversity methods without changing the
established canonical API. The identity hierarchy is metric family,
versioned method, and normalized method-plus-parameter specification.

## Usage

``` r
lexdiv_spec(method_id, parameters = list(), request_id = NULL)

lexdiv_grid(
  method_id,
  parameter,
  values,
  request_id_prefix = NULL,
  max_values = 128L
)

lexdiv_plan(
  presets = "canonical",
  specs = list(),
  grids = list(),
  max_specs = 128L
)

# S3 method for class 'lexdiv_spec'
print(x, ...)

# S3 method for class 'lexdiv_grid'
print(x, ...)

# S3 method for class 'lexdiv_plan'
print(x, ...)

lexdiv_methods()

lexdiv_presets()

lexdiv_profile(tokens, plan = lexdiv_plan())

lexdiv_profile_batch(
  documents,
  plan = lexdiv_plan(),
  id_col = "document_id",
  tokens_col = "tokens",
  max_rows = 1e6
)

lexdiv_screen(
  x,
  floors = c(tokens_50 = 50L, tokens_100 = 100L),
  max_rows = 2e+06
)
```

## Arguments

- method_id:

  One versioned method identifier returned by `lexdiv_methods()`. A
  method fixes its formula, scale, boundary, tail, and aggregation
  rules.

- parameters:

  A plain named list of user-settable method parameters. Omitted values
  are materialized from the versioned defaults.

- request_id:

  An optional plain ASCII identifier used to join one request to its
  profile result.

- parameter:

  The one user-settable scalar parameter admitted by the selected
  current method.

- values:

  A non-empty numeric vector whose elements become distinct method
  specifications after validation and normalization.

- request_id_prefix:

  An optional ASCII prefix for the one-based request IDs generated by
  `lexdiv_grid()`.

- max_values:

  A positive integer bound on values expanded eagerly by one grid call.
  Raise it explicitly only when that allocation is intentional.

- presets:

  A duplicate-free plain character vector selected from
  `lexdiv_presets()`. Use
  [`character()`](https://rdrr.io/r/base/character.html) for a
  custom-only plan.

- specs:

  One `lexdiv_spec`, or a plain list of such objects, appended after
  preset requests.

- grids:

  One `lexdiv_grid`, or a plain list of such objects, appended after
  explicit specifications.

- max_specs:

  A positive integer bound on the number of distinct normalized
  specifications in a plan.

- tokens:

  One pre-tokenized document accepted by
  [`lexdiv_metrics()`](https://ryuya-dot-com.github.io/ldfreq/reference/lexdiv_metrics.md).

- plan:

  A normalized request plan returned by `lexdiv_plan()`.

- documents:

  A named list or data frame/list-column input accepted by
  [`lexdiv_metrics_batch()`](https://ryuya-dot-com.github.io/ldfreq/reference/lexdiv_metrics.md).

- id_col:

  The explicit document-ID column name for data-frame input.

- tokens_col:

  The token-vector list-column name for data-frame input.

- max_rows:

  A positive integer output bound, checked before computation or
  allocation. For `lexdiv_profile_batch()` it bounds
  document-by-specification rows; for `lexdiv_screen()` it bounds
  source-row-by-floor rows.

- x:

  For [`print()`](https://rdrr.io/r/base/print.html), a specification,
  grid, or plan returned by the corresponding constructor. For
  `lexdiv_screen()`, a result returned by `lexdiv_profile()` or
  `lexdiv_profile_batch()`.

- floors:

  A non-empty named numeric vector of positive integer token-count
  screens. Names become `screen_id`; values become `minimum_tokens`.

- ...:

  Additional arguments passed to
  [`print.data.frame()`](https://rdrr.io/r/base/print.dataframe.html).

## Value

`lexdiv_spec()` returns a normalized `lexdiv_spec`; `lexdiv_grid()`
returns an ordered list of specifications; `lexdiv_plan()` returns a
deduplicated `lexdiv_plan` with an MD5 fingerprint over normalized
request identity and order. Their print methods return the input
invisibly after displaying a bounded tabular view; the full identity
fields remain available on the object.

`lexdiv_methods()` returns a metadata data frame with human-readable
labels and definitions, `stability` (including experimental expected-TTR
D), conventional within-method direction, contract scale, exact method
identity, parameters, and advisory token floors. `lexdiv_presets()`
returns a preset metadata data frame. `lexdiv_profile()` returns one
core metric row per plan request with a separate profile envelope.
`lexdiv_profile_batch()` adds the existing batch envelope and returns
document-major, request-minor long form.

`lexdiv_screen()` returns a `lexdiv_screen_results` data frame with one
row per source result and named floor. It deliberately has no
metric-value column.

## Details

Preset version 0.2.0 excludes experimental expected-TTR D. The
`canonical` preset contains eleven methods at their default parameters.
The `length_50_100` preset adds MSTTR at segment length 100 and MATTR at
window length 100. It has thirteen specifications: MTLD is computed only
once because a 50- versus 100-token quality screen does not change its
calculation.

Saved core-contract 0.1.0 plans must be recreated explicitly; see the
migration section in
[`lexdiv_metrics`](https://ryuya-dot-com.github.io/ldfreq/reference/lexdiv_metrics.md).
An explicitly constructed
`lexdiv_spec("expected_ttr_d_hypergeom_fit_v1")` still selects the
experimental estimator.

Duplicate normalized method/parameter specifications from presets,
explicit specifications, or grids collapse at their first position.
Distinct remaining specifications must have distinct request IDs.
Parameter grids form an ordered union, not a cross-product across
metrics. Requested limits are checked before a large result is
allocated. Independently of `max_specs`, a plan rejects more than 1,024
raw preset, explicit-specification, and expanded-grid candidates before
normalization; this prevents an arbitrarily large duplicate input from
bypassing the distinct-specification bound.

The specification, grid, and plan print methods show request, metric,
method, and parameter identity without dumping the internal canonical
identity string. Long vector parameters are abbreviated for display
only. Printing never changes or truncates the stored object.

Profile rows make the method's advisory default floor explicit as
`default_quality_floor_tokens`. Independently requested screens are
non-censoring: they do not change a metric value, effective parameter,
status, or document membership. A 50- or 100-token screen is therefore
not an MTLD method variant, and truncating a document to one of those
lengths would be a separate sampling design. Passing a screen does not
establish measurement validity, reliability, proficiency, or writing
quality; failing one does not invalidate an otherwise computable metric
row.

The profile and screen schemas are distinct from the core metric and
batch schemas. Third-party implementation names are not compatibility
presets; such a preset requires an exact, version-pinned method contract
and boundary fixtures.

## Examples

``` r
methods <- lexdiv_methods()
lexdiv_presets()
#>       preset_id preset_version specification_count
#> 1     canonical          0.2.0                  11
#> 2 length_50_100          0.2.0                  13
#>                                              description
#> 1 The eleven stable methods at their canonical defaults.
#> 2          Canonical plus MSTTR and MATTR at length 100.
mattr_method <- methods$method_id[methods$metric_id == "mattr"]

mattr_25 <- lexdiv_spec(
  mattr_method,
  parameters = list(window_length = 25),
  request_id = "mattr_25"
)

grid <- lexdiv_grid(
  mattr_method,
  parameter = "window_length",
  values = c(50, 100),
  request_id_prefix = "mattr"
)
plan <- lexdiv_plan(presets = character(), specs = mattr_25, grids = grid)
print(mattr_25)
#> <lexdiv_spec: mattr-c60bcc139197f0321525ede59195f383>
#>  request_id metric_id              method_id       parameters
#>    mattr_25     mattr mattr_sliding_step1_v1 window_length=25
print(grid)
#> <lexdiv_grid: 2 specifications>
#>  request_index request_id metric_id              method_id        parameters
#>              1    mattr_1     mattr mattr_sliding_step1_v1  window_length=50
#>              2    mattr_2     mattr mattr_sliding_step1_v1 window_length=100
print(plan)
#> <lexdiv_plan: 3 specifications; schema 0.1.0; id 385893509c8011275b045ea68daa5cb9>
#>  request_index request_id metric_id              method_id        parameters
#>              1   mattr_25     mattr mattr_sliding_step1_v1  window_length=25
#>              2    mattr_1     mattr mattr_sliding_step1_v1  window_length=50
#>              3    mattr_2     mattr mattr_sliding_step1_v1 window_length=100

tokens <- rep(c("a", "b", "a", "c", "d"), 25)
profile <- lexdiv_profile(tokens, plan)
profile[, c("request_id", "metric_id", "value", "status")]
#> <lexdiv_profile_results: 3 specifications; schema unknown>
#>   request_id metric_id value status
#> 1   mattr_25     mattr  0.16     ok
#> 2    mattr_1     mattr  0.08     ok
#> 3    mattr_2     mattr  0.04     ok

screens <- lexdiv_screen(profile)
screens[, c("request_id", "screen_id", "minimum_tokens", "passes_screen")]
#>   request_id  screen_id minimum_tokens passes_screen
#> 1   mattr_25  tokens_50             50          TRUE
#> 2   mattr_25 tokens_100            100          TRUE
#> 3    mattr_1  tokens_50             50          TRUE
#> 4    mattr_1 tokens_100            100          TRUE
#> 5    mattr_2  tokens_50             50          TRUE
#> 6    mattr_2 tokens_100            100          TRUE

documents <- list(document_a = tokens, document_b = rev(tokens))
batch_profile <- lexdiv_profile_batch(documents, plan)
head(batch_profile[, c("document_id", "request_id", "metric_id", "status")])
#> <lexdiv_profile_batch_results: 2 documents; 6 specification results; schema unknown>
#>   document_id request_id metric_id status
#> 1  document_a   mattr_25     mattr     ok
#> 2  document_a    mattr_1     mattr     ok
#> 3  document_a    mattr_2     mattr     ok
#> 4  document_b   mattr_25     mattr     ok
#> 5  document_b    mattr_1     mattr     ok
#> 6  document_b    mattr_2     mattr     ok

all_lengths <- lexdiv_plan("length_50_100")
length(all_lengths$specifications)
#> [1] 13
```
