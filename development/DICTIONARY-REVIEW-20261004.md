# 辞書の記録と文脈別の注釈点検

更新日：2026-10-04。対象：ldfreq 0.2.0開発版のローカル差分。

**辞書の指定・内容照合・保存再実行を既存の `lexdiv_lemmatize()` に追加した。ICNALE原作文140件では、序数・列挙表現55箇所のラベルを変更するとNJ8照合率は変わったが、MATTR50とHD-D42は変わらなかった。** この結果は分析単位の感度を示すものであり、注釈精度の改善や学習者の能力差を実証するものではない。

## 1. 利用者の問題と実装

同じ `textstem` 版を使っていても、辞書が異なれば見出し語化は異なる。版名を利用者が更新し忘れる場合もある。また、語形だけの置換は同じ文字列の異なる用法を区別できない。分析結果だけを保存しても、その生成条件を再現できるとは限らない。

既存APIに `dictionary`、`dictionary_id`、`dictionary_version` を追加した。新しいexportは増やしていない。

- カスタム辞書は2列の文字列data.frame。第1列は現在のロケールで小文字の一意な語形、第2列はlemma。欠測・空文字・重複キーを拒否する。空の辞書では元の表層形を保持する。
- 省略時は `lexicon::hash_lemmas` を明示的に使用し、lexiconの版と実際の表のSHA-256を記録する。textstemとlexiconは任意依存のままである。
- カスタム辞書にはパスを含まないIDと版を要求する。内容ハッシュは同じラベルでも内容が変われば変わり、行順・列名・data.frameの派生classには依存しない。長さを付けたUTF-8の語形・lemmaの組を語形のバイト順で並べて計算する。
- `annotation$dictionary` は由来、ID、版、ハッシュ方式、SHA-256、行数、照合時の `LC_CTYPE` と小文字化方式、未照合時の処理を記録する。辞書表自体は結果に複製しない。再実行には実際の辞書、backend版、ロケールも保存する。
- `lexdiv_content_overlap(unit = "lemma")` はtextstemが関わる場合、両側の辞書ID・版・内容ハッシュ・方式・ロケールが揃い一致することを要求する。供給されたlemma同士の比較やflemmaの既存ルールとは区別する。

前処理契約は0.4.0、overlap契約は0.2.0。0.3.0と0.2.0のUnicode保存オブジェクトは読み込める。古い記録で辞書情報が欠けている場合、欠損同士を「同じ辞書」と判定しない。既知の辞書で再注釈するか、既存の `mismatch` 引数で不確実性を明示して比較する。指標の数式・結果スキーマ・分割規則は変更していない。

ハッシュは内容照合の手掛かりであり、真正性や言語学的正しさの証明ではない。保存済みオブジェクトだけでは、保持していない辞書のハッシュを再計算できない。独立した辞書照合には保存した実体が必要である。

## 2. ICNALEで答えた問いと設計

問いは「同じ原文・分割・計算パラメータのもとで、文脈に応じた一部のlemmaラベル変更は多様性とNJ8照合に何を変えるか」である。研究対象は原作文140件（L2 136、ENS 4）。この140件の平均をL2のみの結果と呼ばない。

保存済みの辞書版・旧ハッシュと現在の実体を照合したうえで、新APIによる注釈が140件すべての保存済みtoken表を完全に再現することを確認した。既存MATTR50とNJ8計算を再利用し、未計算のHD-D42と変更後の計算だけを実行した。評定相関・bootstrap・取り込み処理は繰り返していない。

点検は別々に保存した。

1. **無作為点検**：全原作文の延べtokenから30箇所を無復元抽出、seed 20261004。長い作文ほど選ばれる機会が多く、作文を等確率抽出した標本ではない。`related→relate` の形容詞的使用、`more→much` の比較表現は、POS・lemma schemeによる判断が必要な例として保留した。短縮形 `it's` の保持も分割規則として記録した。この30件から一般的な正解率は推定していない。
2. **問題候補の全件点検**：語の表層形から数字lemmaになった57箇所（44作文）を、前後のtoken列で点検。序数・列挙の55箇所（43作文）はword-formを保持する分析規則に変更した。`one third` の2箇所は分数として区別し、別の規則を決めるまで元の値を保持した。55件を万能な「誤り修正」と称さない。

変更したのは `second` 44、`third` 10、`fourth` 1。document IDとtoken位置、変更前後、理由を保存し、既存の `method = "supplied"` で対象の出現だけを変更した。`lexdiv_compare_annotations()` により原文・分割の一致、55件の差分、前後のprovenanceを確認した。

点検者はassistantであり、独立した人間の注釈者による妥当性確認ではない。問題候補を多く含む抽出と無作為抽出を混ぜて精度を算出しない。POS/mood/tenseでlemmaを細分したCaltabellotta et al. (2026)のschemeの追試でもない。

## 3. 結果と答え

| 指標（原作文140件の単純平均） | 変更前 | 変更後 | 差が生じた作文 |
|---|---:|---:|---:|
| MATTR、窓幅50 | 0.7404410 | 0.7404410 | 0 |
| HD-D、標本サイズ42 | 0.7721828 | 0.7721828 | 0 |
| NJ8 token照合率 | 96.29181% | 96.46498% | 43 |

NJ8照合率の平均差は **+0.17317ポイント**、作文別の最大差は+0.97087ポイント。照合tokenの増分は54であり、変更数55とは異なる。`fourth` は変更後もNJ8では未照合だった。分母となるeligible token数は全作文で不変である。

多様性が変わらなかった理由は、ラベルを変えても各作文の「同じtypeがどこに何回現れるか」が変わらなかったためである。全140作文でlemma列を初出順のtype番号に置き換えた列の完全一致も確認した。したがって今回は語彙表との照合が変わる一方で、MATTR・HD-Dが使う反復構造は変わらない。

答えは「この限定した変更では、照合率と多様性は異なる反応をする」である。照合率が上がったことを辞書の一般的な優越性、妥当性向上、学習成果と解釈しない。分数を含む全用法、品詞推定、複語、別課題への一般化は検証していない。

## 4. 利用手順と成果物

公開用の著者作成例を `vignettes/auditing-vocabulary-profiles.Rmd` に追加した。辞書指定→記録確認→出現位置を指定した注釈変更→差分確認→辞書を含むRDS保存・再読込・再実行を一続きで示す。任意のtextstemがなければその例だけを実行しない。help、NEWS、README、正式契約も更新した。

ローカル実証はworkspaceの以下に保存する。本文・文脈・辞書・個票は公開パッケージに入れない。

- `analysis/icnale-gra/dictionary-sensitivity.R`：再実行スクリプト。
- `analysis/icnale-gra/results/dictionary-review/`：無作為点検、対象点検、変更表、作文ごとの対応表、集計。
- 同directoryの `audit-local.rds`：実際の辞書、変更前後の140作文、注釈差分、計算結果、設定・環境・入力とRソースのハッシュ。

ソフトウェア検証と公開準備の証拠は `reviews/ldfreq-dictionary-20261004/evidence/` に保存する。ローカルのcheck・サイト構築と、公開commitのCI・公開URL確認・CRAN受理は別の状態として扱う。

- 関連テスト、辞書のUnicode・区切り文字・空辞書・行順・保存再読込、内容変更、旧オブジェクト、厳密比較の境界を確認。
- 統合 `R CMD check --no-manual` はStatus OK。testthatは4,817 PASS、FAIL/WARN/SKIPはすべて0。7 vignettesの構築・再構築と例を確認。
- その後、helpの古い契約番号1箇所だけを訂正した。検証済みvignette出力を保持して最終配布物を作り、文書・インストール等を限定checkで再確認（Status OK）。最終配布物と全体check対象との差は当該Rdと自動生成Packaged時刻のみ。成功済みの数値テストは再実行していない。
- API監査は34 exports、30 S3 methods、17 help topics。前処理・overlapのJSON契約は各schemaに適合。
- ICNALEの保存再読込、原注釈の完全一致、変更箇所、分母の不変性、全作文のtype反復列の一致を確認。分析時Rソースと検証対象Rソースも照合した。
