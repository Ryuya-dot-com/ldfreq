Base: `89f0837612dfa5ed29e8ec88737640da85485553`. Package 0.2.0 remains in
development. This record explains the measurement decisions; it is not release
approval or a study validating the measures in a new population.

## Numerical correction versus a changed definition

For expected-TTR D, let `delta_n = 1 - E[TTR(n)]`. On draw `j+1`, condition on
the drawn type having population frequency `f`. The preceding `j` draws sample
`N-1` positions containing `f-1` instances of that type. The probability this
draw repeats a preceding type is
`1 - choose(N-f,j)/choose(N-1,j)`. Weight by `f/N`, sum over types and
`j=1,...,n-1`, and divide by `n`. This gives the expected duplicate fraction
directly. Singletons contribute exactly zero.

The implementation groups equal frequencies and uses `log1p`/`expm1` for the
absence/repeat probabilities. For the existing model
`g(n,D)=2/(sqrt(1+2*n/D)+1)`, the model deficit is
`(2*n/D)/(sqrt(1+2*n/D)+1)^2`. Thus `g-y` can be evaluated as the difference
between the two small deficits without subtracting nearly equal TTR values.
The target, model, objective, parameter domain and optimizer are unchanged.

For one doubleton plus `N-2` singletons,
`E[TTR(n)] = 1-(n-1)/(N*(N-1))`. At `N=1,000,000`, an independent 80-digit
calculation gives `D=511904249956.534883722...`; the prior implementation gave
about `466769084020`, 8.8% lower. `verify-expected-ttr-d.py` reproduces the
reference with direct high-precision subtraction and linear-D bisection.
The package regression uses relative tolerance `1e-12`.

Decision: retain `expected_ttr_d_hypergeom_fit_v1` and core contract 0.1.0 as a
documented numerical correction. The operation-order description in the
contract is amended explicitly. Package version remains necessary for exact
reproduction. This does not solve the estimator's near-saturation sensitivity.

MTLD's minimum complete factor length and unclamped residual, by contrast, are
part of its mathematical definition. On a repeated single type, lengths 59 and
60 produce approximately 7.22 and 10 under the frozen rules. Clamping would
change the method, so this revision documents and tests the boundary without
silently inventing another estimator.

## Comparison and preprocessing boundaries

Metric names and plan-local request IDs cannot distinguish different windows.
Wide and plotted comparison groups now require one contract/method/parameter
identity. Missing rows retain their requested condition even when effective
parameters are empty. Wide defaults retain counts and parameters; plotted data
retain the selected result's full metadata.

Preprocessing contract 0.2.0 requires the recorded pattern, text hashes,
character counts and a canonical token-table hash, and checks normalization,
case, number policy and offset consistency. It excludes annotation columns
from the token hash so legitimate annotation APIs remain usable. Old objects
must be recreated from original text. This catches ordinary edits and missing
records, not forged provenance or incorrect human/external annotations.

## TUBELEX is a separate preparation pipeline

The pinned upstream resource uses Penn Treebank segmentation, while the
package's Unicode tokenizer preserves contractions. A matched whole contraction
does not prove aligned tokenization. Contract 0.2.0 rejects known generic
tokenization objects by default and records an explicit mismatch override;
character vectors remain caller-prepared and unverified. No unvalidated
Treebank imitation is added. The new apostrophe transform changes typography
only and is opt-in; the previous character-term default remains unchanged.

`tubelex_profile_batch()` uses the existing per-document profile calculation
and one lazy resource snapshot scoped to that call. It retains the full result,
uses existing document-ID validation, and checks a planned lookup/summary row
budget before loading. Failed loads are shared consistently within the batch;
new calls verify a new snapshot. It introduces no global cache or dependency.

## Verification and scope

Run the installed testthat suite, the repository public-API audit, and
`R CMD build` / `R CMD check --no-manual`. The normal check also runs the
existing differential, cross-language and resource-integrity audit scripts.
`verify-review-fixes.R` supplies 100 additional independently computed
hypergeometric targets and `optimize()` fits, plus measured batch equivalence,
load count and row-budget checks. `verify-expected-ttr-d.py` is a development
tool, excluded from the installed package; mpmath is not a runtime dependency.

Local results on R 4.6.1 / macOS 26.6.2 (arm64):

- Source build and vignette build succeeded; `R CMD check --no-manual` finished
  with `Status: OK`, including vignette rebuilding. Testthat reported
  `FAIL 0 | WARN 0 | SKIP 0 | PASS 4299`.
- The existing independent audit passed 500 MTLD documents, 1,000 direct
  formula/window/hypergeometric documents, and 73,809 exhaustive comparisons.
- The 100 additional D cases had maximum absolute target-curve error
  `1.67e-15` and maximum relative difference from the independent optimizer
  `2.2e-8`; the near-saturation fixture passed its `1e-12` relative tolerance.
- Ten short documents took 8.878 seconds separately versus 1.650 seconds in
  one batch in one measured run. Full outputs were identical, resource loads
  were exactly one per batch call, and the row-budget rejection occurred
  before loading. These timings are environment-specific, not a guarantee.
- Public-API audit: 30 exports, 28 registered S3 methods, 14 help topics.
  Source/platform/installed resource audit: 1,137 assertions, 30 members with
  byte-identical payloads across all three forms.
- Release-workflow version pins and artifact names advance to 0.2.0 while
  `Status: development` is retained. The extracted state classifier accepts
  development/candidate records and rejects wrong version, package, scope,
  and unknown status (six checks). Actual GitHub Actions were not run locally.

The check could not reach CRAN/Bioconductor indexes in this restricted
environment; installed-dependency checks passed, but this is not an online
`--as-cran` run. No Linux, Windows, minimum-R or R-devel result is claimed here.
